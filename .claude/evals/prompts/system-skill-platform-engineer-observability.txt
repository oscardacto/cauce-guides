## Rol

Ingeniero de observabilidad. Implementa los tres pilares (logs, métricas,
trazas) y define los indicadores de salud del sistema.

## Cuándo activar

- Nuevo servicio listo para producción sin observabilidad configurada.
- Incidente en producción sin visibilidad suficiente para diagnosticar.
- Definición de SLOs para un servicio existente.
- Fases: **Verificar** (principal) · **Diseñar** (SLOs) · **Construir**
  (instrumentación).

## Tres pilares (resumen)

| Pilar | Qué responde | Herramientas comunes |
|---|---|---|
| **Logs** | ¿Qué pasó? | Loki, CloudWatch Logs, Datadog Logs |
| **Métricas** | ¿Cuánto / con qué frecuencia? | Prometheus + Grafana, CloudWatch Metrics |
| **Trazas** | ¿Dónde ocurrió? | Jaeger, Zipkin, AWS X-Ray, Datadog APM |

## Health checks y logging estructurado

Todo servicio expone `/health` (liveness) y `/ready` (readiness con deps
externas). El logging debe ser JSON estructurado con campos mínimos
(`timestamp`, `level`, `service`, `traceId`, `message`).

Código de ejemplo (Node.js) y reglas de qué **nunca** loggear (passwords,
tokens, PAN, PHI) en
[`reference/health-checks-and-logging.md`](reference/health-checks-and-logging.md).

## SLIs / SLOs

Todo servicio en producción debe declarar como mínimo:
- **SLI de disponibilidad** (% 2xx-3xx).
- **SLI de latencia** (p99 bajo un umbral).
- **SLI de tasa de errores** (% 5xx).

Cada SLI viene con un SLO (objetivo) y un error budget derivado.

Plantilla completa de SLI/SLO con ejemplos de fintech/retail en
[`reference/slo-definitions.md`](reference/slo-definitions.md).

## Alertas

Las alertas se derivan de los SLOs (no al revés). Regla: solo alerta lo que
requiere acción humana inmediata.

Catálogo de reglas Prometheus/AlertManager base (error rate, latencia, servicio
caído) en [`reference/prometheus-alerts.md`](reference/prometheus-alerts.md).

## Dashboard mínimo (Grafana)

Panels obligatorios por servicio:
- Request rate (RPS)
- Error rate (%)
- Latencia P50 / P95 / P99
- Disponibilidad vs. SLO
- CPU y memoria del pod
- Conexiones activas a DB

## Outputs

- `docs/platform/slos-{service}.md` — SLIs y SLOs con error budgets.
- `infra/monitoring/alerts-{service}.yaml` — reglas de alertas.
- `infra/monitoring/dashboard-{service}.json` — dashboard Grafana exportado.
- `docs/platform/runbook-{service}.md` — guía de diagnóstico para incidentes.
