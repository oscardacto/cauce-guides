## Rol

Validador responsive. Define la estrategia de breakpoints del sistema y verifica que la UI se adapte correctamente en todos los contextos de visualización.

## Cuándo activar

- Se define o revisa la estrategia de breakpoints del proyecto
- Un layout nuevo necesita validación responsive
- Se reportan problemas de visualización en dispositivos específicos
- Fases: **Diseñar, Construir**

## Estrategia de breakpoints (mobile-first)

```css
/* Breakpoints sugeridos — ajustar según el proyecto */
--bp-sm:  640px;   /* Teléfonos grandes */
--bp-md:  768px;   /* Tablets portrait */
--bp-lg:  1024px;  /* Tablets landscape / laptops pequeños */
--bp-xl:  1280px;  /* Desktops */
--bp-2xl: 1536px;  /* Pantallas grandes */
```

## Checklist de validación responsive

### Layout
- [ ] Columnas colapsan correctamente en mobile (< 640px)
- [ ] Navegación principal se convierte en menú hamburguesa en mobile
- [ ] Tablas tienen scroll horizontal o colapsan a card en mobile
- [ ] Imágenes usan `max-width: 100%` y no desbordan el contenedor

### Tipografía
- [ ] Tamaños de fuente son legibles en pantallas pequeñas (mínimo 14px)
- [ ] Line-height adecuado para lectura en mobile
- [ ] No hay overflow de texto fuera del contenedor

### Interacción táctil
- [ ] Targets táctiles ≥ 44×44px (WCAG 2.5.5)
- [ ] Elementos interactivos tienen espacio suficiente entre sí
- [ ] Hover states tienen equivalente táctil (active state)

### Rendimiento
- [ ] Imágenes con `srcset` o `<picture>` para diferentes densidades
- [ ] No se cargan recursos innecesarios en mobile

## Formato de guía de breakpoints

```markdown
## Responsive Guide — {Feature / Sistema}

### Breakpoints del proyecto
| Token | Valor | Uso |
|---|---|---|
| `sm` | 640px | Mobile landscape, teléfonos grandes |
| `md` | 768px | Tablets portrait |
| `lg` | 1024px | Tablets landscape, laptops |
| `xl` | 1280px | Desktops |

### Comportamiento por componente
| Componente | < sm | sm–md | md–lg | > lg |
|---|---|---|---|---|
| Navbar | hamburger | hamburger | horizontal | horizontal |
| Grid | 1 col | 2 col | 3 col | 4 col |
```

## Outputs

- `docs/design/responsive-guide.md` — estrategia de breakpoints y comportamiento por componente

## Cuándo NO invocar

- La consulta es sobre accesibilidad (touch targets ≥44px, navegación) — usar `ux-ui-accessibility`.
- Se requiere especificar comportamiento por estado/variante — usar `ux-ui-component-spec`.
- Se trabaja sobre design tokens base — usar `ux-ui-design-tokens`.


## Anti-patterns

- **Breakpoints copiados de Bootstrap sin justificar** — los breakpoints deben corresponder al contenido del proyecto (donde el layout "se rompe"), no a defaults arbitrarios. Validar con datos reales de devices del segmento de usuarios.
- **Mobile-first declarado pero desktop-first implementado** — CSS con `@media (max-width: ...)` cascadeando hacia abajo. Mobile-first real: estilos base son mobile, `@media (min-width: ...)` agrega complejidad para pantallas mayores.
- **Misma cantidad de información en mobile que desktop** — comprimir 12 columnas a 1 fila scrolleable infinita degrada la experiencia. Re-priorizar contenido en mobile (qué se oculta tras "ver más", qué cambia de orden).
- **Touch targets pequeños** — botones de 24×24px que pasan en mouse pero son inalcanzables en mobile. WCAG 2.5.5: targets ≥ 44×44px en interacción táctil.
