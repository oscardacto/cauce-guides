## Dominio activo: Educación

Skill cargado cuando el proyecto opera en el dominio educativo o EdTech. Activo como soporte transversal en todas las fases.

## Flujos críticos del dominio

### Flujo de aprendizaje
```
Descubrimiento → Inscripción → Acceso al contenido →
  Progreso (lección a lección) → Evaluación → Certificación
```

### Estados de inscripción
`no_inscrito → inscrito → en_progreso → completado | abandonado | vencido`

### Flujo de evaluación
```
Inicio del quiz → Preguntas (aleatorias o fijas) →
  Envío de respuestas → Calificación automática →
    Aprobado (≥ umbral) | Reprobado → Reintento permitido | Bloqueado
```

### Flujo de certificación
```
Curso completado → Criterios verificados (nota, asistencia, actividades) →
  Generación de certificado → Firma digital → Disponible para descarga / LinkedIn
```

## Reglas de negocio frecuentes

- El progreso se calcula como `lecciones_completadas / total_lecciones * 100`
- Una lección se considera completada cuando el estudiante alcanza el criterio definido (ej: ver 80% del video)
- Las evaluaciones pueden tener intentos limitados, tiempo máximo y nota mínima aprobatoria
- El contenido puede tener prerrequisitos — lección B no disponible hasta completar lección A
- Los certificados deben ser verificables — incluir código único y URL de verificación
- En gamificación: los puntos y rangos deben ser consistentes y transparentes para mantener motivación

## Cuándo NO invocar

- El proyecto no es LMS, contenido educativo, evaluaciones ni certificaciones — contexto genérico.
- La consulta es sobre accesibilidad de UI sin contexto educativo — usar `ux-ui-accessibility` directamente.
- Diseño general de microservicios — usar `architect-bounded-context`.

## Anti-patterns de dominio

- **SCORM en móvil**: SCORM fue diseñado para web desktop — tiene limitaciones serias en mobile
- **Video como unidad de progreso**: el tiempo de reproducción es manipulable — complementar con checkpoints o quizzes
- **Offline learning**: apps móviles educativas deben soportar descarga y sincronización — el progreso offline debe sincronizarse al reconectar
- **Cohortes vs. self-paced**: cursos con fecha de inicio/fin tienen lógica diferente a cursos de acceso libre permanente
- **Certificado generado pero no verificable** — PDF sin URL pública de validación. Cada certificado lleva código único + URL firmada.
- **xAPI statements sin LRS** — si se usa xAPI, el LRS es obligatorio; sin él los statements son log inútil.
