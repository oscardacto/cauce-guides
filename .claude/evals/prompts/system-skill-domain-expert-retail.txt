## Dominio activo: Retail / Ecommerce

Skill cargado cuando el proyecto opera en el dominio retail o comercio electrónico. Activo como soporte transversal en todas las fases.

## Flujos críticos del dominio

### Flujo de compra
```
Búsqueda / Navegación → PDP → Agregar al carrito → Checkout →
  Selección de envío → Pago → Confirmación → Fulfillment → Entrega
```

### Flujo de inventario
```
Compra (reserva stock) → Pago confirmado (descuento stock) →
  Cancelación/Devolución (reposición stock)
```

### Ciclo de vida de un pedido
`creado → pago_pendiente → pago_confirmado → en_preparación → despachado → entregado | devuelto | cancelado`

### Flujo de devolución (RMA)
```
Solicitud de devolución → Aprobación → Guía de retorno →
  Recepción en almacén → Inspección → Reembolso / Cambio
```

## Reglas de negocio frecuentes

- El stock se **reserva** al agregar al carrito (soft hold) y se **descuenta** al confirmar el pago
- Un producto puede tener múltiples variantes (talla, color) — cada combinación es un SKU distinto
- Los precios pueden variar por canal, lista de precios, segmento de cliente o promoción activa
- Las promociones tienen prioridad y pueden ser excluyentes o acumulables
- En marketplace: el precio lo fija el seller, el marketplace cobra comisión sobre el GMV
- Las devoluciones tienen ventanas de tiempo (típico 30 días) y condiciones (producto sin usar, con etiqueta)
- El inventario en omnicanal debe estar unificado — el stock de la tienda física es disponible para retiro o despacho

## Cuándo NO invocar

- El proyecto no involucra catálogos, inventario, checkout ni operaciones de venta — contexto genérico.
- La consulta es sobre pasarela de pagos en sí — usar `domain-expert-fintech`.
- Diseño general de microservicios — usar `architect-bounded-context`.

## Anti-patterns de dominio

- **Race condition en stock**: múltiples compradores intentando el último ítem — requiere lock optimista o reserva con TTL
- **Precio en el momento del checkout**: el precio puede cambiar entre agregar al carrito y confirmar — definir política explícita
- **Impuestos**: varía por país, tipo de producto y tipo de comprador (B2C vs B2B)
- **Peso volumétrico**: el costo de envío puede calcularse por peso físico o volumétrico (el mayor)
- **Cancelación sin reposición de stock** — toda transición a `cancelado` o `devuelto` debe disparar evento de reposición auditado.
- **Promociones acumulables sin tope** — apilar descuentos puede generar precio negativo. Definir reglas de exclusividad y validar descuento total contra mínimos de margen.
