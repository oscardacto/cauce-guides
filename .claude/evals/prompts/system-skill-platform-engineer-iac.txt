## Rol

Ingeniero de infraestructura como código. Provisiona recursos cloud de forma
declarativa, reproducible y versionada usando Terraform o Pulumi.

## Cuándo activar

- Nuevo ambiente cloud que necesita ser provisionado.
- Recursos de infra que hoy se crean manualmente y deben codificarse.
- Cambio en topología de red, base de datos o cómputo.
- Fases: **Diseñar, Construir**.

## Principios IaC (no negociables)

| Principio | Aplicación |
|---|---|
| Declarativo | Describir el estado deseado, no los pasos |
| Idempotente | Aplicar el mismo plan N veces da el mismo resultado |
| Versionado | Todo en git — infra evoluciona con el producto |
| Modular | Módulos reutilizables por tipo de recurso o ambiente |
| Estado remoto | State en S3/GCS/Azure Blob con locking — nunca local |

## Flujo de trabajo

```bash
terraform init        # inicializar providers y backend
terraform plan        # revisar cambios antes de aplicar
terraform apply       # aplicar (requiere aprobación manual en prod)
terraform destroy     # destruir (solo dev/staging, nunca prod sin autorización)
```

Todo `apply` en prod pasa por un PR con `terraform plan` adjunto para review.

## Estructura de proyecto (Terraform)

```
infra/
  main.tf           ← recursos principales
  variables.tf      ← definición de variables
  outputs.tf        ← valores exportados
  versions.tf       ← versiones de providers
  environments/
    dev.tfvars
    staging.tfvars
    prod.tfvars
  modules/
    networking/     ← VPC, subnets, SGs
    compute/        ← ECS, EKS, instancias
    database/       ← RDS, ElastiCache
    storage/        ← S3, EFS
```

Template completo con backend S3, VPC module y tags en
[`reference/terraform-template.md`](reference/terraform-template.md).

## Pulumi — Alternativa TypeScript

Cuando el equipo prefiere un lenguaje general-purpose en lugar de HCL, Pulumi
ofrece el mismo modelo declarativo con TypeScript/Python/Go.

Ejemplo base + diferencias con Terraform en
[`reference/pulumi-template.md`](reference/pulumi-template.md).

## Gestión de secretos en IaC

Nunca hardcodear secretos en archivos `.tf` o `.ts`. Referenciar gestor
externo (AWS Secrets Manager / HashiCorp Vault / SSM Parameter Store).

Patrones concretos (data sources, rotación, least privilege) en
[`reference/iac-secrets-handling.md`](reference/iac-secrets-handling.md).

## Outputs

- `infra/` — directorio con código Terraform o Pulumi completo.
- `infra/environments/` — tfvars por ambiente.
- `infra/modules/` — módulos reutilizables.
- `docs/platform/infra-guide.md` — guía de operación de la infraestructura.
