# Migración ASDD — 3.3.x → 3.4.0

Release **MINOR** en el template, **MINOR** en el contrato CLI (`2.3.0 → 2.4.0`).
No hay cambios de comportamiento del framework: todo lo de abajo es **ubicación de
archivos** y **qué se distribuye**. Ningún agente, skill, hook ni regla cambia de
semántica.

## Resumen de incompatibilidades

| En 3.3.x | En 3.4.0 | Acción requerida |
|---|---|---|
| El manual del framework vivía en `docs/adoption/`, `docs/validation.md`, `docs/mcps-by-domain.md`, `docs/plugins-by-role.md`, `docs/migrations/` | Vive en `.claude/docs/**` | Actualizar tus enlaces internos si documentaste rutas del manual |
| `dashboard/` en la raíz del proyecto | `.claude/dashboard/` | Cambiar tus invocaciones: `node .claude/dashboard/generate-report.js` |
| Se distribuían artefactos de desarrollo del ASDD (auditorías, ADRs del framework, changelog) | No se distribuyen | Borrado manual de 8 rutas — ver abajo |
| `npm test` figuraba como paso de validación para repos que instalan ASDD | Solo aplica al repositorio template | Usar `node .claude/scripts/validate-template.mjs` |

## Antes de migrar

1. Confirmá tu versión actual: `.sofka-asdd/sofka-asdd.lock` → `version`.
2. Commiteá o guardá tu trabajo pendiente. La actualización toca `.claude/**`, y si
   personalizaste algo ahí el CLI te lo preserva como `<archivo>.asdd-new` para que
   lo concilies — pero es más fácil hacerlo con el árbol limpio.
3. Si tenés artefactos propios bajo `docs/testing/`, `docs/adoption/` o `docs/` raíz,
   anotá cuáles: el paso 2 de abajo borra rutas del framework en esas carpetas y
   querés distinguir lo tuyo antes de borrar nada.

## Pasos de actualización

### 1. Instalar la distribución 3.4.0

Con el CLI (`sofka upgrade`) o copiando la distribución declarada en
`.sofka-asdd/cli-contract.json`. Las rutas nuevas relevantes:

- `.claude/docs/` — ahora incluye el manual completo del framework (adoption, validación,
  catálogos de MCPs y plugins, guías de migración).
- `.claude/dashboard/` — el generador de reportes ATF Web, antes en la raíz.
- `.claude/scripts/sofka-asdd-regen-hashes.mjs` — **nuevo en la distribución**. Es la
  única vía admitida para regenerar los hashes SHA-256 si personalizás una referencia
  de regla bajo `.claude/references/`. Antes no se distribuía y el fallo del validador
  no tenía salida documentada.
- `.gitattributes` — **nuevo en la distribución**. Fija la política de fin de línea (LF
  para código y config, CRLF para `.ps1`/`.bat`/`.cmd`). Sin él, un equipo mixto
  Windows/Linux vuelve a producir diffs fantasma por EOL.

### 2. Borrar los artefactos de desarrollo del framework que quedaron huérfanos

El CLI copia lo que declara `distribution`, pero **no borra** lo que dejó de declarar.
Estas 8 rutas se te instalaron en versiones anteriores y ya no forman parte del
template. Son documentos internos del desarrollo del ASDD: auditorías, ADRs del
framework e historia de versiones.

```bash
# Revisá primero que no tengas trabajo propio en estas rutas.
rm -f docs/testing/2026-08-03-001-VERIFY-001-preexisting-test-suite-defects.md
rm -f docs/testing/2026-08-03-001-VERIFY-002-cli-distribution-cross-os-gaps.md
rm -f docs/testing/2026-08-03-001-VERIFY-003-framework-governance-gaps.md
rm -f ASDD-CHANGELOG.md
rm -f docs/adoption/ADR-002-smart-data-flow-isolation.md
rm -f docs/adoption/ADR-004-spec-per-area-model.md
rm -f docs/adoption/ADR-006-integracion-capa-ba-analista-funcional.md
rm -f docs/adoption/ADR-007-git-guards-threat-model-reenfoque.md
rm -f docs/architecture/decisions/ADR-020-workspace-multirepo-y-worktree-gestionado.md
rm -f .sofka-asdd/checklist.json
```

En PowerShell, `Remove-Item -Force <ruta>` para cada una.

> **`docs/testing/` NO se borra completa.** Sigue siendo donde viven tus corridas ATF y
> las semillas de configuración (`appweb.yaml`, `appapi.yaml`,
> `credentials.yaml.example`). Solo se borran los 3 archivos `*VERIFY-*` listados.

Si `docs/adoption/` queda vacío después del borrado, podés eliminar la carpeta: el
manual que te interesa ahora está en `.claude/docs/adoption/`.

### 3. Actualizar tus invocaciones del dashboard

Buscá en tus notas, scripts y pipelines:

```bash
grep -rn "dashboard/generate-" . --include="*.md" --include="*.sh" --include="*.yml"
```

Y cambiá `dashboard/` por `.claude/dashboard/`. Los artefactos del template ya vienen
actualizados; esto es solo para lo que hayas escrito vos.

> **Bonus:** este movimiento corrige un defecto latente. `generate-report.js` resolvía
> la ruta del exportador a Excel como hermano de `dashboard/`, que desde la fusión con
> el template apuntaba a un directorio inexistente. Estaba envuelto en un
> `fs.existsSync`, así que la exportación de la matriz de CPs a `.xlsx` **fallaba en
> silencio**. Con el dashboard bajo `.claude/`, la ruta resuelve correctamente.

### 4. Habilitar los prerequisitos de Windows (si aplica)

Si tu equipo trabaja en Windows, dos ajustes que el CLI no puede hacer por vos:

```bash
git config core.longpaths true    # rutas > 260 chars en corridas ATF anidadas
bash --version                    # debe responder: Git Bash de Git for Windows
```

El segundo no es opcional: reglas y skills ejecutan pipelines POSIX
(`find … | wc -l`, `read -ra`, `tr`/`xargs`). Tener solo el binario `git` no alcanza.

## Validación posterior

Ejecutar desde la raíz de tu proyecto:

```bash
node .claude/scripts/validate-template.mjs
```

Resultado esperado: **`0 errores`**. Los warnings de presupuesto de contexto no
bloquean la adopción, pero no deben ocultarse como PASS.

> Las suites `test-*.mjs` **no se distribuyen y no van a distribuirse**: verifican el
> comportamiento interno de hooks y scripts del framework, no la configuración de tu
> proyecto. `npm test` no aplica en un proyecto consumidor.

Si el validador reporta `SHA-256 mismatch` y **vos personalizaste** una referencia de
regla bajo `.claude/references/`, es esperado. Regeneralo:

```bash
node .claude/scripts/sofka-asdd-regen-hashes.mjs
```

Nunca calcules el hash a mano con `sha256sum`, `certutil` o `Get-FileHash`: no
normalizan fin de línea ni BOM y contaminan el manifiesto.

## Rollback

Esta migración no cambia formatos de estado ni de manifiestos, así que volver atrás es
restaurar el árbol anterior:

1. `git checkout` del commit previo a la actualización (o restaurar tu backup).
2. Reinstalar la distribución 3.3.x.

No hay migración de datos que revertir: `.asdd-run.json`, `rule-loading.json` y
`coordinator-loading.json` conservan el mismo esquema.
